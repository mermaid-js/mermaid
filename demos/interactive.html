Interactive, Parameterised Mermaid Diagrams

A proof-of-concept for extended Mermaid syntax — combining reusable templates with declarative interaction behaviours (tooltips, collapsible nodes).

Example 1: Inline Interaction Blocks

Hover over Service A and Service B for tooltips. Click the API Gateway node to collapse its children.

Source (.mermid)
graph TD
  A[Client] --> B[API Gateway]
  B --> C[Service A]
  B --> D[Service B]

  interaction B {
    collapsible: true
    defaultState: expanded
  }

  interaction C {
    tooltip: "Handles authentication logic"
  }

  interaction D {
    tooltip: "Handles billing operations"
  }

Example 2: Parameterised Template

The template is expanded before rendering. Hover endpoints for tooltips. Click the service hub to collapse.

Source (.mermid)
template service_flow(serviceName, endpoints[]) {
  graph TD
    A[Client] --> B[serviceName]
    B --> C[endpoints[0]]
    B --> D[endpoints[1]]

    interaction B {
      collapsible: true
      defaultState: expanded
    }

    interaction C {
      tooltip: "Primary endpoint"
    }

    interaction D {
      tooltip: "Secondary endpoint"
    }
}

use service_flow(
  serviceName="Auth API",
  endpoints=["Login", "Token Refresh"]
)

Example 3: Combined Template + Collapsible Microservice Group

The hub starts collapsed. Click it to reveal the services. Hover each service node for its tooltip.

Source (.mermid)
template microservice_group(name, services[]) {
  graph TD
    GW[Gateway] --> HUB[name]
    HUB --> SVC0[services[0]]
    HUB --> SVC1[services[1]]
    HUB --> SVC2[services[2]]

    interaction HUB {
      collapsible: true
      defaultState: collapsed
    }

    interaction SVC0 {
      tooltip: "Core business service"
    }

    interaction SVC1 {
      tooltip: "Secondary supporting service"
    }

    interaction SVC2 {
      tooltip: "Background worker / async processor"
    }
}

use microservice_group(
  name="Order Platform",
  services=["Order Service", "Inventory Service", "Notification Service"]

Example 4: Subgraph with Individual Node Interactions

Node B is collapsible — clicking it hides C and D1 (and the outgoing lines) but preserves the A→B connection. The A→D1 edge crosses the subgraph boundary. Hover each node for its tooltip.

Source (.mermid)
graph TD
  A[Client] --> B[Load Balancer]
  B --> C[Auth Service]
  B --> D1
  A --> D1

  subgraph SG1 [Backend Services]
    D1[Order Service]
    D2[Inventory Service]
    D3[Notification Service]
    D1 --> D2
    D2 --> D3
  end

  interaction B {
    collapsible: true
    defaultState: expanded
    tooltip: "Distributes incoming traffic"
  }

  interaction C {
    tooltip: "Validates JWT tokens and API keys"
  }

  interaction D1 {
    tooltip: "Order creation and management"
  }

  interaction D2 {
    tooltip: "Tracks stock levels in real time"
  }

  interaction D3 {
    tooltip: "Sends email and push notifications"

Example 5: Subgraph as Interaction Target

The interaction is attached to the subgraph group itself, not to individual nodes. Clicking the subgraph boundary collapses all internal nodes and every edge crossing the boundary — compare with Example 4 where only B’s direct children collapse.

Source (.mermid)
graph TD
  A[Client] --> B[Load Balancer]
  B --> C[Auth Service]
  B --> D1
  A --> D1

  subgraph SG1 [Backend Services]
    D1[Order Service]
    D2[Inventory Service]
    D3[Notification Service]
    D1 --> D2
    D2 --> D3
  end

  interaction SG1 {
    collapsible: true
    defaultState: expanded
    tooltip: "Backend Services group - click to collapse entire subgraph"
  }

  interaction B {
    tooltip: "Distributes incoming traffic"
  }

  interaction C {
    tooltip: "Validates JWT tokens and API keys"

Example 7: E-commerce Domain Model — classDiagram

Class diagrams use a different SVG ID scheme (classId-{Name}). Click Customer or Order to collapse their associated classes. Hover any class for its domain role.

Source (.mermid)
classDiagram
  class Order {
    +String id
    +Date createdAt
    +OrderStatus status
    +calculateTotal() Float
  }
  class Customer {
    +String id
    +String email
    +String tier
    +placeOrder() Order
  }
  class Product {
    +String sku
    +String name
    +Float price
    +Int stock
  }
  class OrderItem {
    +Int quantity
    +Float unitPrice
  }
  class Payment {
    +String provider
    +String status
    +confirm() Boolean
  }

  Customer "1" --> "0..*" Order : places
  Order "1" *-- "1..*" OrderItem : contains
  OrderItem "0..*" --> "1" Product : references
  Order "1" --> "1" Payment : settled by

  interaction Order {
    tooltip: "Purchase record. Status transitions: pending -> confirmed -> shipped -> delivered"
    collapsible: true
  }
  interaction Customer {
    tooltip: "Registered buyer. Tier (standard/gold/platinum) affects pricing and SLA"
    collapsible: true
  }
  interaction Product {
    tooltip: "Catalogue item. stock is decremented atomically on OrderItem creation"
  }
  interaction OrderItem {
    tooltip: "Line item. unitPrice is locked at purchase time, independent of Product.price changes"
  }
  interaction Payment {
    tooltip: "Delegated to payment provider (Stripe/Adyen). confirm() is called by webhook"
  }

Example 8: Order Lifecycle — stateDiagram-v2

State diagrams render states as g.stateGroup SVG elements. Click Pending to collapse the entire downstream lifecycle, or click Shipped to collapse the post-dispatch branch. Hover any state for its business rule.

Source (.mermid)
stateDiagram-v2
  [*] --> Pending
  Pending --> Confirmed : payment_received
  Pending --> Cancelled : payment_timeout
  Confirmed --> Processing : warehouse_allocated
  Processing --> Shipped : dispatched
  Shipped --> Delivered : delivery_confirmed
  Shipped --> ReturnRequested : return_raised
  Delivered --> ReturnRequested : return_raised
  ReturnRequested --> Refunded : return_received
  Cancelled --> [*]
  Delivered --> [*]
  Refunded --> [*]

  interaction Pending {
    tooltip: "Awaiting payment. Auto-cancelled after 30 min via scheduled job."
    collapsible: true
  }
  interaction Confirmed {
    tooltip: "Payment captured. Warehouse notified for stock allocation."
  }
  interaction Processing {
    tooltip: "Stock allocated. Pick-pack-ship workflow active in WMS."
  }
  interaction Shipped {
    tooltip: "Carrier has collected. Tracking events streamed via webhook."
    collapsible: true
  }
  interaction Delivered {
    tooltip: "Carrier confirmed delivery. 30-day return window starts."
  }
  interaction ReturnRequested {
    tooltip: "Customer initiated return. RMA raised, prepaid label emailed."
  }
  interaction Refunded {
    tooltip: "Return received and inspected. Refund posted within 3-5 business days."
  }
  interaction Cancelled {
    tooltip: "Order void. If payment was captured it is automatically refunded."
  }
