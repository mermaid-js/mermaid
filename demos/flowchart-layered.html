Flowchart LAYERED

These examples exercise the built-in layered layout (layout: layered): ranks, subgraphs, edge routing modes, line hops, node shapes and the other graph diagrams it lays out. Edit the diagrams to inspect different results.

Basic flow with a cycle

Nodes are placed in ranks along the diagram direction. The edge back to B is reversed. 

---
config:
  layout: layered
---
flowchart TD
  A([Start]) ==> B[Step 1]
  B ==> C{Flow 1}
  C -- Choice 1.1 --> D[Step 2.1]
  C -- Choice 1.3 --> I[Step 2.3]
  C == Choice 1.2 ==> E[Step 2.2]
  D --> F{Flow 2}
  E ==> F
  F == Choice 2.1 ==> H[Feedback node]
  H ==> B
  F == Choice 2.2 ==> G((Finish))

Subgraphs with their own direction

Edges can start or end at a subgraph, and a subgraph can set its own direction.

---
config:
  layout: layered
---
flowchart LR
  subgraph build [Build]
    direction TB
    compile --> test
  end
  subgraph release [Release]
    tag --> publish
  end
  checkout --> build
  build --> release

Nested subgraphs and inner edges

An edge between a subgraph and a node inside it (Outer → Parse) runs along the flow, and the subgraph grows to keep its label clear. 

---
config:
  layout: layered
---
flowchart TB
  In[Input] --> Outer
  subgraph Outer [Outer]
    subgraph Inner [Inner]
      a1[Parse] --> a2[Check]
    end
    Inner -->|report| b1[Store]
    Outer -->|start| a1
  end
  Outer -->|done| Out[Output]
  a2 --> Out

Edge routing: rounded (default)

Edges run on tracks with small circular corners.

---
config:
  layout: layered
  layered:
    edgeRouting: rounded
---
flowchart TD
  A --> B
  A --> C
  A --> D
  B --> E
  C --> E
  D --> E

Edge routing: stepped

The same tracks, with each turn softened over at most 12 px.

---
config:
  layout: layered
  layered:
    edgeRouting: stepped
---
flowchart TD
  A --> B
  A --> C
  A --> D
  B --> E
  C --> E
  D --> E

Edge routing: curved

Each edge runs as smooth curves between ranks and keeps its own interpolation, so A → B is straight. 

---
config:
  layout: layered
  layered:
    edgeRouting: curved
---
flowchart TD
  A --> B
  A --> C
  A --> D
  B --> E
  C --> E
  D --> E
  linkStyle 0 interpolate linear

Edge routing: straight

Each edge runs as straight lines from point to point.

---
config:
  layout: layered
  layered:
    edgeRouting: straight
---
flowchart TD
  A --> B
  A --> C
  A --> D
  B --> E
  C --> E
  D --> E

Line hops: arc (default)

Where two edges cross, the edge that gives way hops over the other.

---
config:
  layout: layered
---
flowchart TD
  A --> B
  A --> C
  A --> D
  A --> E
  B --> C
  B --> D
  B --> E
  C --> D
  C --> E
  D --> E

Line hops: gap

The edge that gives way is broken around the other.

---
config:
  layout: layered
  layered:
    lineHops: gap
---
flowchart TD
  A --> B
  A --> C
  A --> D
  A --> E
  B --> C
  B --> D
  B --> E
  C --> D
  C --> E
  D --> E

Edge labels, self-loops and parallel edges

Labels are placed on their edges, self-loops get room for their labels, and parallel edges run side by side. 

---
config:
  layout: layered
---
flowchart LR
  Idle -->|start| Running
  Running -->|tick| Running
  Running -->|pause| Paused
  Running -->|suspend| Paused
  Paused -->|resume| Running
  Running -->|stop| Idle
  Running -->|fail| Error
  Error -->|reset| Idle

Node shapes

Edges end on each shape's outline, including non-convex shapes such as the bolt.

---
config:
  layout: layered
---
flowchart TB
  start@{ shape: circle, label: "Start" } --> doc@{ shape: doc, label: "Document" }
  start --> db@{ shape: cyl, label: "Database" }
  doc --> bolt@{ shape: lightning-bolt }
  db --> bolt
  bolt --> hex@{ shape: hex, label: "Prepare" }
  bolt --> dec@{ shape: diam, label: "Decide" }
  hex --> stop@{ shape: dbl-circ, label: "Stop" }
  dec --> stop

Styles, classes and linkStyle

Node classes and per-edge styles work as with the other layouts.

---
config:
  layout: layered
---
flowchart LR
  A[Request]:::in --> B{Valid?}
  B -->|yes| C[Handle]:::ok
  B -->|no| D[Reject]:::bad
  C --> E[Respond]
  D --> E
  classDef in fill:#e3f2fd,stroke:#1565c0
  classDef ok fill:#e8f5e9,stroke:#2e7d32
  classDef bad fill:#ffebee,stroke:#c62828
  linkStyle 2 stroke:#c62828,stroke-width:2px,stroke-dasharray:4 3

Requirement diagram

---
config:
  layout: layered
---
requirementDiagram
  requirement test_req {
    id: 1
    text: the test text.
    risk: high
    verifymethod: test
  }
  functionalRequirement test_req2 {
    id: 1.1
    text: the second test text.
    risk: low
    verifymethod: inspection
  }
  element test_entity {
    type: simulation
  }
  test_entity - satisfies -> test_req2
  test_req - contains -> test_req2

Mindmap

Mindmaps are drawn as a top-down tree.

---
config:
  layout: layered
---
mindmap
  root((Layered))
    Ranks
      Cycles
      Long edges
    Routing
      Rounded
      Stepped
      Curved
      Straight
    Subgraphs
