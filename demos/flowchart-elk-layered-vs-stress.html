ELK Layout Algorithm Comparison

Layered vs Stress-Minimization Layouts

The same directed graph rendered with two fundamentally different ELK algorithms. elk.layered assigns nodes to horizontal layers following edge direction — the result is an unmistakable top-down hierarchy. elk.stress places nodes so visual distances match graph-theoretic distances, producing an organic layout with no notion of layers.

Algorithm Overview:

  • elk.layered (left): Assigns nodes to layers so edges generally flow in one direction. Produces a clean, hierarchical "org chart" layout. Best for DAGs, flowcharts, and dependency graphs.
  • elk.stress (right): Minimizes the difference between visual distances and graph-theoretic distances. Produces a compact, organic shape — no concept of layers or directions. Best for general graphs where spatial proximity should reflect connectivity.

Layered will show a clear top-down hierarchy; stress will fold the same graph into an organic blob. The difference is immediate and unmistakable.

Why not elk.force vs elk.stress?

The intuitive comparison would be force-directed vs stress-minimization — they sound like opposites. But both algorithms solve the same underlying problem with similar mathematics: place nodes so the visual distance between them matches their graph-theoretic distance (hop count). Fruchterman-Reingold force simulation and stress majorization converge to nearly identical layouts on most graphs, especially DAGs and moderately connected networks. They look the same in practice.

elk.layered is a completely different class of algorithm — it assigns nodes to discrete ranks (layers) before placing them, which produces a fundamentally different visual structure. Comparing layered to stress is comparing hierarchical ranking to distance preservation, which are genuinely distinct layout philosophies that produce unmistakably different pictures.

Layered Layout (elk.layered)

Algorithm: elk.layered — the ELK default
Characteristics: Assigns nodes to layers; edges flow top-to-bottom
Best for: Flowcharts, DAGs, dependency trees

Stress-Minimization Layout (elk.stress)

Algorithm: elk.stress — optimization-based placement
Characteristics: Organic placement, no layers, visual distance ≈ graph distance
Best for: General graphs, network topology, circular layouts
