Grid-attached layout

grid-decomposed with the decomposition put back together. The core is laid out by grid-like — every core node sits where grid-like put it, with all its alignments intact — and every tree HOLA's leaf peeling removed is hung back onto the core node it came from. Where it hangs is HOLA's answer (guide §17): largest tree first, into the angular wedge of a face at its root, cardinal direction before ordinal, external face before internal.

Which grid-like drawing of the core to keep is this layout's choice. grid-like's beautification is greedy and never undone, so on a core this small the drawing that comes out flips on sub-pixel changes to the derived grid spacing: the four-cycle below came out four different ways, only one of them the obvious rectangle. So grid-like is asked several times — over the knobs the paper leaves open, never a change to its algorithm — and the drawing with the fewest edges through nodes, then crossings, then unaligned pairs is kept. grid-decomposed keeps drawing its cores exactly as it did.

The core's edges are this layout's own, though its node positions are not. grid-like draws each edge as a straight line between two node centres; on a grid-like drawing many of those are axis-aligned, but any pair the alignment pass did not align gets a diagonal — and a diagonal is free to run straight through a third node's box, which it does. So the routes are replaced, and the positions are not, by orthogonal ones from HOLA's own router, which avoids the node rectangles, prefers few bends and penalises both crossing an edge already routed and running along one. This is what HOLA itself does: an orthogonally routed core is its Step 2c, and the straight centre-to-centre line is an IPSEP-COLA convention.

The one liberty taken with the core's layout is enlargement. HOLA makes room for a tree by expanding the face around it, which moves core nodes and would destroy the alignments that make a grid-like drawing grid-like. So instead every core node is moved away from the core's centre by a common factor: every core edge gets longer and nothing else changes — the same picture, more room. That factor is raised only as far as it pays for itself against the dead stubs it saves.

A wide fan — one node, many connectors

Every connector leaving one side of one node gets its own attachment point, and the fan's turns are nested into a comb so each run sits on its own line. Without either, all eight arrive as one thick stem and one thick bar and no reader can tell which arrow goes where. The rank gap is widened to hold the comb rather than being fixed, so a chain still gets a tight gap and only a fan pays for the room it needs.

Edge labels — room to sit, and clear of crossings

Two things decide where a label goes. A tree's rank gap is widened to hold the labels it carries, because a label is drawn centred on its connector and so needs clearance at both ends — without it a tall label fills the gap and touches both nodes, leaving no room for the arrowhead. Then the label may slide along any run of its own route, never off it, to keep clear of node boxes, other labels, foreign routes, and above all the point where two edges cross: a label sitting on a crossing belongs, as far as a reader can tell, to either of them.

A tree on a busy core node — attaching beside what is already there

E is where the two cycles meet, so it carries a core edge on each of its four sides, and a tree hangs off it as well. The core's ports and the tree's are chosen by different passes — the core's by HOLA's router, the tree's by this layout — so the tree's have to be told what is already taken, or a lone connector keeps the centre of its side and lands exactly where a lone core edge already is. Nothing about the core moves: the side is cut into the stretches its edges leave free and the tree attaches in one of those.

Non-rectangular shapes — connectors land on the shape, not on its box

The layout works in rectangles, but a diamond does not reach the corners of its own bounding box. A fan forces the issue: two children means two ports and neither can sit at a vertex, so a port placed out along a bounding-box side leaves the arrow starting in the empty gap between the box and the shape. Both diamonds below carry a fan of two, and both fans spread only over what the shape can accept.
