Grid-decomposed layout

HOLA's topological decomposition (undirected leaf peeling: trees removed from the core), with every resulting part drawn on its own by grid-like and packed beside the others. Each peeled tree is re-rooted on a duplicate of the core node it hung from, drawn with a dashed outline: the edge peeling cut is still drawn, from the duplicate, so no edge ever runs between two parts and nothing is lost. A core always contains a cycle, so it is laid out without the flow ordering — otherwise the cycle collapses into a single column with its closing edge running back through the nodes in between.

Core with two trees (TB)

---
config:
  layout: grid-decomposed
---
flowchart TB
  A --> B
  B --> C
  C --> D
  D --> A
  A --> t1
  t1 --> t2
  t2 --> t3
  C --> s1
  s1 --> s2

Edge labels and a self-loop

Parse -- error --> Report is the edge peeling cuts, so it is drawn inside the tree part, running from the duplicated Parse — label included. The self-loop travels with the tree part that owns Report. 

---
config:
  layout: grid-decomposed
---
flowchart TB
  Start --> Parse
  Parse -- ok --> Layout
  Layout --> Render
  Render --> Start
  Parse -- error --> Report
  Report --> Report

HOLA paper graph 8 — a four-cycle core with one subtree

The paper's own example, and the case that showed up the two bugs this layout had: the core must read as the cycle A—B—C—D—A, and the peeled subtree must carry a duplicate of D as its root. 

---
config:
  layout: grid-decomposed
---
flowchart TB
  A --- B
  B --- C
  C --- D
  D --- A
  D --- E
  E --- F
  E --- G
  E --- H
  G --- I
  G --- L
