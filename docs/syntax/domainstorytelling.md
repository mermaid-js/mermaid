# Domain Storytelling (Beta, v\<MERMAID_RELEASE_VERSION>+)

Domain Storytelling diagrams model business interactions as ordered sentences between actors and work objects.

Use Domain Storytelling when you want to document collaborative behavior in a domain without switching to a low-level technical flowchart.

## Syntax

Start every diagram with `domainstorytelling-beta`.

```mermaid-example
domainstorytelling-beta

A_Customer : 01 -- "places" -> W_Order
A_Service : 02 -- "processes" -> W_Order
```

```mermaid
domainstorytelling-beta

A_Customer : 01 -- "places" -> W_Order
A_Service : 02 -- "processes" -> W_Order
```

### Naming Rules

- Actors start with `A_`, work objects with `W_`, groups with `G_`, and optional sentence ids with `S_`. After the prefix, use letters, digits, and underscores — `A_BackOffice` and `A_Back_Office` both work, while a dash (`A_back-office`) is a parse error.
- Only the prefix is stripped for the fallback label, so `A_Back_Office` renders as `Back_Office`. Declare a label to control the wording.
- Sequence numbers always have at least two digits: `01`–`09` for the first nine steps, then `10`, `11`, and so on. A bare `1` or a `00` is a parse error.

### Declarations

You can declare labels, icons, and group membership before sentences. When no
label is declared, the identifier is shown without its prefix — `A_Customer`
renders as `Customer` and `W_Order` as `Order`.

```mermaid-example
domainstorytelling-beta

group G_FrontOffice "Front Office"

A_Customer "Customer" person in G_FrontOffice
A_Clerk "Service Clerk" person in G_FrontOffice
W_Order "Purchase Order" document

A_Customer : 01 -- "places" -> W_Order
A_Clerk : 02 -- "reviews" -> W_Order
```

## Sentences

The core sentence pattern is:

```text
A_Actor : 01 -- "activity" -> W_WorkObject
```

### Optional Sentence Id

Sentence ids give annotations a stable target. They are required once a sequence number
appears more than once: `annotate sentence 01` then fails as ambiguous, and the id has to
be used instead.

```mermaid-example

A_Agent : 01 -- "resolves" -> W_Ticket id S_ResolveTicket
```

## Icons

Icons are declared on actor or work object declarations.

### Built-in Icons

Mermaid ships a built-in icon pack covering the basic Domain Storytelling notation, so these icons render without any setup. They are referenced by bare name:

| Icon           | Intended for |
| -------------- | ------------ |
| `person`       | Actors       |
| `people`       | Actors       |
| `system`       | Actors       |
| `document`     | Work objects |
| `folder`       | Work objects |
| `call`         | Work objects |
| `email`        | Work objects |
| `conversation` | Work objects |
| `info`         | Work objects |

Actors with no icon fall back to `person`, work objects to `document` — so undeclared
actors and work objects still render as icon nodes.

### Iconify Icon Packs

Beyond the built-in set, any [Iconify](https://iconify.design) icon can be used in `pack:icon` form (for example `fa6-solid:user` or `mdi:account`).

The referenced icon pack must be registered before rendering with `mermaid.registerIconPacks(...)`. If the pack isn't registered, a placeholder icon is drawn.

```js
mermaid.registerIconPacks([
  {
    name: 'logos',
    loader: () =>
      fetch('https://unpkg.com/@iconify-json/logos/icons.json').then((res) => res.json()),
  },
]);
```

```mermaid-example
A_PaymentProvider logos:paypal
```

## Annotations

Domain Storytelling supports annotations for actors, groups, sentences, and work object instances.

```mermaid-example
domainstorytelling-beta

group G_Service "Service Desk"
A_Agent in G_Service
A_Customer

A_Customer : 01 -- "reports" -> W_Ticket id S_Report
A_Agent : 02 -- "closes" -> W_Ticket id S_Close

annotate actor A_Agent "Handles escalations."

annotate group G_Service "Internal operating context."

annotate sentence 01 "Triggered by a customer request."

annotate sentence S_Close "Final state transition."

annotate workobject W_Ticket@S_Close "Closed ticket instance."
```

```mermaid
annotate sentence S_Close "Final state transition."

annotate workobject W_Ticket@S_Close "Closed ticket instance."
```

Annotation targets must already exist: an undeclared actor or group, an unknown sentence
reference, or a work object that appears more than once in the referenced sentence all
raise an error rather than being ignored.

## Configuration

Configure Domain Storytelling layout via frontmatter under `config.domainstorytelling`.

```mermaid-example
---
config:
  domainstorytelling:
    rankdir: TB
    nodeSpacing: 60
    rankSpacing: 120
---
domainstorytelling-beta
A_Customer : 01 -- "places" -> W_Order
A_Service : 02 -- "processes" -> W_Order
```

```mermaid
---
config:
  domainstorytelling:
    rankdir: TB
    nodeSpacing: 60
    rankSpacing: 120
---
domainstorytelling-beta
A_Customer : 01 -- "places" -> W_Order
A_Service : 02 -- "processes" -> W_Order
```

| Key              | Type    | Allowed Values         | Default |
| ---------------- | ------- | ---------------------- | ------- |
| `rankdir`        | string  | `TB`, `BT`, `LR`, `RL` | `LR`    |
| `nodeSpacing`    | number  | `>= 0`                 | `70`    |
| `rankSpacing`    | number  | `>= 0`                 | `130`   |
| `diagramPadding` | number  | `>= 0`                 | `8`     |
| `useMaxWidth`    | boolean | `true`, `false`        | `true`  |

The global `layout` option is honored as well: `dagre` is used by default, and `elk` when
the ELK layout package has been registered. An unregistered algorithm falls back to dagre.

> **Note**: The `handDrawn` look has no effect on this diagram type. Actors and work objects are icon nodes with no shape outline to sketch, and the look is intentionally not applied to connectors or group frames.
